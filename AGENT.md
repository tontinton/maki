# AGENT.md

This file provides guidance to agentst such as Maki, Claude Code, etc. when working with code in this repository.

## What is Maki

Maki is a high-performance, context-efficient AI coding agent written in Rust. It provides a native TUI (ratatui, 60 FPS) and optimizes for minimal token usage. It supports multiple LLM providers (Anthropic, OpenAI, Google, Mistral, Z.AI, Ollama) and ships with 17+ built-in tools plus MCP support.

## Build & Test Commands

Uses `just` (justfile runner) + cargo. Rust 1.85+ (2024 edition) required.

```bash
just build          # cargo build --all-features
just test           # cargo nextest run --all-features --workspace
just lint           # cargo clippy --all-features --all --tests -- -D warnings
just lint-fix       # cargo clippy --fix
just fmt            # cargo fmt + stylua plugins/
just fmt-check      # check formatting (Rust + Lua)
just pylint         # ruff check + ty check on scripts/
just gen-docs       # regenerate docs via maki-docgen
just gen-docs-check # verify generated docs are current
just ci             # full CI: fmt-check lint pylint test gen-docs-check
```

Run a single test:
```bash
cargo nextest run --all-features --workspace -E 'test(test_name_here)'
```

## Architecture

Rust workspace with 11 crates in the root directory:

- **maki-ui** — TUI frontend, Elm-like architecture (state -> view -> event -> update), syntect for highlighting, nucleo for fuzzy search
- **maki-agent** — Async agent loop on smol runtime, 17+ built-in tools, three-layer permission system, MCP client, skill system
- **maki-providers** — Single interface over multiple LLM HTTP APIs, streaming, token counting, retries, prompt caching
- **maki-config** — Two-layer TOML config (global `~/.config/maki/config.toml` + project `.maki/config.toml`), preserves comments on writes
- **maki-storage** — Persistent state under `~/.maki` (sessions, auth, history, logs), crash-safe atomic writes
- **maki-code-index** — Tree-sitter based compact skeleton generation (70-90% smaller), supports 15+ languages behind feature gates
- **maki-lua** — WIP Neovim-inspired Lua plugin system using mlua (LuaU dialect), sandboxed execution
- **maki-interpreter** — Python sandbox via pydantic/monty, isolates user code from host
- **maki-tool-macro** — Proc macro for tool implementation and registry wiring
- **maki-config-macro** — Proc macro for config system
- **maki-docgen** — Generates markdown docs for tools, commands, config, providers, keybindings

Tools live in `maki-agent/src/tools/`. Plugins in `plugins/`. Site/docs in `site/`.

## Code Guidelines

- No trivial comments — comments explain WHY, not WHAT
- Minimal bloat (KISS, DRY, SRP) — each line must justify its existence
- No unnecessary state (variables, fields, arguments)
- No wildcard imports
- Import types at top, use short names everywhere (e.g. `use std::sync::Arc;` then `Arc<T>`)
- Consts at top of file, right after imports
- No inline magic numbers or strings
- Explicit error handling with `Result<T, E>` — use `color_eyre` for general errors, `thiserror` for domain-specific
- Add `#[derive(Copy)]` only on structs with 1 primitive field
- Add dependencies to workspace `Cargo.toml` first, then `workspace = true` in the crate
- Try solving with existing deps before adding new ones
- Be mindful of allocations in hot paths
- Prefer structured logging with contextual fields

## Testing Conventions

- Unit tests in the same file using `#[cfg(test)]` modules
- Use `#[test_case]` for parametrized tests, snake_case test names
- In tests, const error/status messages and assert against the shared constant
- No tautological tests
- Lua tests use `_spec.lua` suffix
